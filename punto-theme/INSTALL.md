# Punto — WordPress Theme Install Guide

A faithful classic-PHP port of the static Punto site. Same markup, CSS, JS,
fonts and copy — the EN/IT toggle, pricing sliders, mouse dot and hover lifts
all behave exactly as on the static version.

---

## 1. Zip the theme

From inside the `punto-theme/` folder:

```bash
cd punto-theme
zip -r ../punto-theme.zip . -x ".*"
```

This produces `punto-theme.zip` one level up.

> The zip's top-level folder must be `punto-theme/` with `style.css` and
> `functions.php` directly inside it. Zipping the folder itself (as above) is
> correct — don't zip from inside a parent that renames it.

---

## 2. Upload & activate

1. WordPress admin → **Appearance → Themes → Add New → Upload Theme**.
2. Choose `punto-theme.zip` → **Install Now** → **Activate**.

---

## 3. Make the homepage show `front-page.php`

The homepage template (`front-page.php`) renders automatically once your
front page is set to a static page:

1. Create a page: **Pages → Add New**, title it `Home`, **Publish** (leave the
   body empty — all content lives in the template).
2. **Settings → Reading → "Your homepage displays" → A static page**.
3. Set **Homepage** to `Home`. **Save Changes**.

Visit the site — it should look identical to the GitHub version, with the
EN/IT toggle, sliders and interactions working.

> Language is handled **client-side** by the EN/IT toggle, exactly like the
> static site (default English, choice remembered in the browser). There is no
> separate `/en/` page in this faithful port — switching is instant, no reload.

---

## 4. (Optional) Use a real WordPress menu

The header navigation works out of the box via hard-coded fallback links. To
manage it from the admin instead:

1. **Appearance → Menus → Create a new menu**.
2. Add **Custom Links** (URL `#design`, `#social`, `#pricing`, `#process`,
   `#portfolio`, `#contact`) with the matching labels.
3. Assign it to the **Primary Menu** location.

Leaving this untouched keeps the identical default header — it's purely
optional.

---

## 5. (Optional) Interior pages — Privacy / Terms / Cookies

The footer links (`Privacy`, `Terms`, `Cookies`) currently point to `#`. To
make real pages, create them under **Pages → Add New**; they render through
`page.php` inside the Punto shell. Update the footer hrefs in `footer.php` to
their permalinks when ready.

---

## 6. Where the WooCommerce work goes (later)

The theme already declares `add_theme_support('woocommerce')` and is safe with
WooCommerce **inactive** (all Woo calls are guarded with `function_exists()`).

The three design-package **Book** buttons are generated by JavaScript, so their
TODO lives in two clearly-commented spots:

- **`front-page.php`** — the `#design` section, comment block `WOOCOMMERCE TODO`.
- **`assets/js/main.js`** — function `renderDesignPackages()`, comment
  `WOOCOMMERCE TODO`. Swap each button's `href` from `#contact` to a real
  add-to-cart URL, e.g. `/?add-to-cart=<PRODUCT_ID>`.

Recommended plugin order (test after each): **WooCommerce** → **WooCommerce
Stripe Gateway** → **WFatture (Fatture in Cloud)** for SDI e-invoices.

## File tree

```
punto-theme/
├── style.css            WordPress theme header (metadata)
├── functions.php        Enqueue CSS/JS/fonts, menu, WooCommerce support, JSON path
├── header.php           <!DOCTYPE> … site header / nav
├── footer.php           Footer + wp_footer() + closing tags
├── front-page.php       The full homepage (all sections)
├── index.php            Generic fallback template
├── page.php             Standard interior-page template
├── screenshot.png       Theme preview (Appearance → Themes)
├── INSTALL.md           This file
└── assets/
    ├── css/styles.css   The real design stylesheet (byte-for-byte)
    ├── js/
    │   ├── i18n.js      Language system (reads JSON path from window.PUNTO)
    │   ├── pricing.js   Dynamic pricing calculator
    │   ├── main.js      Renders sections, nav, contact form
    │   └── interactive.js  Mouse dot, grid glow, hover states
    └── data/
        ├── en.json      English content
        └── it.json      Italian content
```

## Notes / limitations

- **Google Fonts** are loaded from Google (same URL as the static site). If you
  prefer self-hosting, download the fonts into `assets/fonts/` and point the
  `punto-fonts` enqueue in `functions.php` at a local `@font-face` stylesheet.
- **Contact form** uses the original `mailto:` fallback (opens the visitor's
  email client). For server-side sending, add a plugin like Contact Form 7 or
  WPForms later — the markup is standard and easy to swap.
- The theme intentionally keeps all copy as **static markup in the templates**
  (not in the WP editor), matching the brief.
